Attività: modifiche non richieste, da leggere e annullare

Durata indicativa: 25 minuti. Si lavora sulla palestra (prenotazione dei laboratori, dati inventati), nel repository del vostro PC.

La situazione

Avete chiesto a un agente di aggiungere all'elenco delle prenotazioni un filtro per laboratorio: node cli.js elenco --lab LAB-INF1. L'agente ha fatto il filtro, ha lanciato i test, sono tutti verdi, e ha consegnato. Il suo commit è l'ultimo del ramo.

Il vostro compito: capire cosa ha cambiato, tenere solo quello che avevate chiesto e annullare il resto, un pezzo alla volta.

Passi

  1. Controllate di non avere modifiche da salvare e partite dal punto noto. git status git switch -c lavoro-a2 partenza-a2 node --test

  2. Leggete il commit dell'agente. git log --oneline git show --stat HEAD git diff HEAD~1 HEAD Scrivete un elenco: per ogni file e ogni blocco di righe, "richiesto" oppure "non richiesto". Se un blocco non è chiaro, chiedetelo all'agente: non annullatelo a caso.

  3. Provate anche a mano. Ci sono comportamenti che i test non coprono: lanciate qualche comando della palestra e confrontate con quello che ricordate o con il ramo main (git switch main, riprovate, poi tornate con git switch lavoro-a2). Attenzione: prenota scrive in dati/dati.json; dopo una prova riportatelo com'era con git restore dati/dati.json, altrimenti git switch può rifiutarsi di cambiare ramo.

  4. Annullate le modifiche non richieste una per una, ognuna in un commit con un messaggio chiaro. Strumenti utili:

    • git restore --source=main percorso/del/file per riportare un file intero com'è in main;
    • git restore -p --source=main percorso/del/file per scegliere i blocchi;
    • git rm percorso/del/file per togliere un file aggiunto;
    • modificare a mano una riga, o chiedere all'agente di annullare una sola cosa precisa;
    • git diff e git status dopo ogni passo. Non usate reset --hard né stash.

  5. Verifica finale. git diff main --stat git diff main node --test Devono restare solo le righe del filtro per laboratorio (--lab). Se manca il filtro, o è rimasto qualcos'altro, tornate al punto 4.

  6. A coppie: confrontate il vostro elenco con quello del vicino. Avete trovato le stesse cose? Chi ne ha trovate di più, dove le ha viste?

Se qualcosa va storto

  • Un annullamento ha tolto anche il filtro: git revert <id-del-commit> annulla l'annullamento, oppure ripartite con un altro ramo (git switch -c lavoro-a2-bis partenza-a2). Il lavoro vecchio resta sul ramo di prima.
  • git status mostra file che non riconoscete: non cancellateli con comandi generali, guardate prima cosa sono.

Sul vostro progetto

Se il vostro progetto ha già un repository, fate lo stesso controllo: git status, git diff, poi commit con i file per nome.
