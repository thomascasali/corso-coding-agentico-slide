Installare l'agente: Claude Code e OpenCode sul PC del laboratorio

Si installano due agenti da terminale, Claude Code e OpenCode, e li si collega al server del corso con la vostra chiave personale. Poi si aggiunge un kit minimo per leggere PDF, Word ed Excel. Il PC è un PC Windows del laboratorio, con il vostro utente: non servono permessi di amministratore.

Funzioni e comandi sono quelli della documentazione ufficiale letta il 25/11/2026: Claude Code, uv, MarkItDown, OpenCode. Di OpenCode si usa la serie 1 (versione 1.19.5).

Tutti i comandi si incollano in PowerShell, uno alla volta, premendo Invio dopo ciascuno. Nei comandi compaiono due segnaposto da sostituire con i dati del foglio consegnato in aula, prima di premere Invio:

  • <indirizzo del server> è l'indirizzo del server del corso, con la porta, come sta sul foglio.
  • <la tua chiave> è la vostra chiave personale. Vale come una password: non si mostra a nessuno.

Per ogni passo c'è un punto di controllo: se non torna, non passate al successivo.

Passo 1. Installare Claude Code

Aprite PowerShell dal menu Start: il prompt comincia con PS. Incollate il comando; mentre scarica non mostra avanzamento.

irm https://claude.ai/install.ps1 | iex

Quando il prompt torna, chiudete la finestra e apritene una nuova: il percorso dei programmi si aggiorna solo nelle finestre aperte dopo.

claude --version

Punto di controllo. Esce un numero di versione seguito da (Claude Code). Se dice che claude non è riconosciuto, chiudete e riaprite ancora la finestra, poi chiamate il docente.

Passo 2. Indirizzo e chiave come variabili dell'utente

Sul foglio l'indirizzo ha la forma indirizzo:porta. Sostituite <indirizzo del server> nel comando con quello del foglio, senza /v1 e senza barra in fondo, poi premete Invio.

[Environment]::SetEnvironmentVariable("ANTHROPIC_BASE_URL", "http://<indirizzo del server>", "User")

Il valore User la rende una variabile dell'utente: non serve l'amministratore e la vedono le finestre aperte da ora in poi, non quelle già aperte.

Per la chiave si usa la finestra delle variabili, non PowerShell:

  1. Menu Start: scrivete variabili e scegliete la voce che finisce con relative all'account, non quella di sistema.
  2. Nella lista in alto premete Nuova.
  3. Nome: incollate il nome qui sotto. Valore: incollate la chiave dal foglio. Confermate con OK su tutte le finestre.
ANTHROPIC_AUTH_TOKEN

Poi aprite una finestra PowerShell nuova e controllate. Il primo comando non mostra la chiave:

if ($env:ANTHROPIC_AUTH_TOKEN) { "chiave presente" } else { "chiave mancante" }

$env:ANTHROPIC_BASE_URL

Punto di controllo. Il primo scrive chiave presente. Il secondo scrive l'indirizzo del foglio, con http:// davanti e senza /v1 in fondo.

Passo 3. Prima prova di connessione

Una richiesta diretta al server, con le due variabili appena create. Si scrive curl.exe con l'estensione, perché curl da solo in PowerShell è un altro comando.

curl.exe "$env:ANTHROPIC_BASE_URL/v1/models" -H "Authorization: Bearer $env:ANTHROPIC_AUTH_TOKEN"

Punto di controllo. Esce una riga di testo con claude-sonnet-5-5 e claude-haiku-5-5. Una risposta con 401 dice che la chiave è sbagliata; nessuna risposta dice che indirizzo o porta sono sbagliati, o che il PC è fuori dalla rete consentita.

Ora Claude Code, in una cartella di prova. Tre comandi, uno alla volta:

New-Item -ItemType Directory -Force "$env:USERPROFILE\prova-agente" | Out-Null

cd "$env:USERPROFILE\prova-agente"

claude --permission-mode manual

Claude Code si apre senza schermata di accesso. Se chiede di accedere con un account, la variabile della chiave non è arrivata: uscite con /exit, aprite una finestra nuova e rifate il controllo del passo 2.

Dentro Claude Code incollate la richiesta:

Rispondi con una parola: collegato.

Poi scrivete /status e leggete due righe: Anthropic base URL deve essere il vostro server; Auth token deve nominare ANTHROPIC_AUTH_TOKEN.

Punto di controllo. L'agente risponde e le due righe sono quelle. Uscite con /exit.

Se dice che il modello non è disponibile, riavviate con il modello scritto per esteso:

claude --permission-mode manual --model claude-sonnet-5-5

Passo 4. OpenCode sul server

Node.js c'è già, quindi OpenCode si installa con npm, nella versione fissata per il corso:

npm install -g opencode-ai@1.19.5

opencode --version

Punto di controllo. Esce 1.19.5. Se Windows chiede la password di amministratore, fermatevi e chiamate il docente. Non usate /connect dentro OpenCode: salverebbe la chiave in un file.

Due comandi per il file di configurazione. Il primo crea la cartella, il secondo apre il file in Blocco note; se chiede di crearlo, rispondete di sì:

New-Item -ItemType Directory -Force "$env:USERPROFILE\.config\opencode" | Out-Null

notepad "$env:USERPROFILE\.config\opencode\opencode.json"

Incollate nel Blocco note tutto il testo qui sotto. Sostituite <indirizzo del server> con quello del foglio, con il /v1 già scritto in fondo. Non c'è nessuna chiave: il file legge la variabile. Al salvataggio il nome deve restare opencode.json, non opencode.json.txt: scegliete «Tutti i file».

{
  "$schema": "https://opencode.ai/config.json",
  "enabled_providers": ["anthropic"],
  "provider": {
    "anthropic": {
      "options": {
        "baseURL": "http://<indirizzo del server>/v1",
        "apiKey": "{env:ANTHROPIC_AUTH_TOKEN}",
        "headers": {
          "Authorization": "Bearer {env:ANTHROPIC_AUTH_TOKEN}"
        }
      },
      "whitelist": ["claude-sonnet-5-5", "claude-haiku-5-5"]
    }
  },
  "model": "anthropic/claude-sonnet-5-5",
  "small_model": "anthropic/claude-haiku-5-5",
  "share": "disabled",
  "autoupdate": false,
  "permission": {
    "*": "ask",
    "read": {
      "*": "allow",
      "*.env": "deny",
      "*.env.*": "deny",
      "*.env.example": "allow"
    },
    "glob": "allow",
    "grep": "allow",
    "list": "allow",
    "todowrite": "allow",
    "question": "allow",
    "edit": "ask",
    "bash": {
      "*": "ask",
      "git status *": "allow",
      "git diff *": "allow",
      "git log *": "allow",
      "rm *": "deny",
      "git push *": "deny"
    },
    "task": "ask",
    "skill": "ask",
    "webfetch": "deny",
    "websearch": "deny",
    "external_directory": "deny"
  }
}

Dopo aver cambiato variabili o file, OpenCode va chiuso del tutto: un processo rimasto in secondo piano non vede le variabili create dopo la sua partenza. Se il comando non scrive niente, non c'erano processi aperti: va bene.

Get-Process opencode* -ErrorAction SilentlyContinue | Stop-Process -Force

opencode models

Punto di controllo. L'elenco ha due righe: anthropic/claude-sonnet-5-5 e anthropic/claude-haiku-5-5. Se ce ne sono altre, il file non è stato letto: ricontrollate virgole, virgolette e nome del file.

Prima richiesta, nella cartella di prova:

cd "$env:USERPROFILE\prova-agente"

opencode

Dentro OpenCode incollate:

Rispondi con una parola: collegato.

Punto di controllo. OpenCode risponde. Se resta fermo senza errori, quasi sempre l'indirizzo o la porta nel file sono sbagliati. Per uscire: /exit.

Passo 5. Il kit minimo: uv e MarkItDown

uv esegue programmi Python al volo e si porta Python da solo. MarkItDown trasforma PDF, Word, Excel e PowerPoint in testo Markdown, tabelle comprese. Si parte da uv, solo per il vostro utente:

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Chiudete la finestra e apritene una nuova, poi:

uv --version

Punto di controllo. Esce uv seguito da un numero di versione.

Con uvx MarkItDown non si installa: uv lo scarica la prima volta e lo tiene in una cache. Quella prima volta è lenta e scrive molte righe; lanciatela adesso, così non capita davanti a un PDF. Non interrompetela.

uvx --from "markitdown[all]" markitdown --help

Punto di controllo. Alla fine compare il testo di aiuto di markitdown e il prompt torna. Eventuali righe su FontBBox sono innocue.

Passo 6. Le istruzioni globali

Un file che l'agente legge a ogni avvio: dice che gli strumenti del kit ci sono e si possono usare, e che una tabella spezzata va dichiarata, non indovinata. Lo stesso testo va in due file, uno per agente. Aprite il primo, incollate il testo qui sotto, salvate con «Tutti i file» (il nome resta CLAUDE.md, non .txt):

notepad "$env:USERPROFILE\.claude\CLAUDE.md"

# Istruzioni per l'agente

Lavori per un docente di informatica. Rispondi in italiano, con frasi brevi.

## Leggere i documenti

Per leggere un PDF, un file Word, Excel o PowerPoint non aprirlo come testo: convertilo con MarkItDown, con questo comando (sostituisci il nome del file):

uvx --from "markitdown[all]" markitdown nome-del-file.pdf

Poi lavora sul testo ottenuto. Se il comando scrive avvisi sui caratteri del PDF, ignorali. Se una tabella esce con righe spezzate o colonne mescolate, dillo e non indovinare i valori mancanti.

## Calcoli e tabelle

Per conteggi, percentuali e confronti tra valori usa Python con le librerie caricate al volo, per esempio:

uv run --with pandas python nome-dello-script.py

Per leggere o scrivere file Excel usa uv run --with openpyxl python nome-dello-script.py. Non fare i conti a mente: calcolali.

## Risultati

Scrivi i risultati in file nella cartella di lavoro (Markdown, CSV o Excel), non solo nella chat.

## Cosa non fare

- Non installare programmi. I comandi uvx e uv run scritti qui sopra sono permessi.
- Non modificare i documenti originali (PDF, Word, Excel): scrivi i risultati in file nuovi.
- Non cancellare file senza chiedere.
- Non inviare niente a nessuno (email, messaggi, caricamenti) senza chiedere prima.
- Alla fine scrivi che cosa non hai potuto verificare.

Poi il secondo, con lo stesso testo (il nome resta AGENTS.md):

notepad "$env:USERPROFILE\.config\opencode\AGENTS.md"

I file si leggono quando parte la sessione: dopo averli salvati, aprite una sessione nuova.

Punto di controllo. I due file esistono con il testo dentro e il Blocco note non dice «.txt» nel titolo.

Passo 7. Prova su un PDF

Scaricate il PDF di prova, prova-markitdown.pdf, dalla pagina dei materiali di questo argomento: sono poche righe di prenotazioni di laboratorio inventate. Poi copiatelo nella cartella di prova. Se il browser lo ha salvato altrove o con un altro nome, adattate il percorso.

Copy-Item "$env:USERPROFILE\Downloads\prova-markitdown.pdf" "$env:USERPROFILE\prova-agente\"

Sessione nuova, nella cartella di prova (cd come al passo 3). Avviate Claude Code:

claude --permission-mode manual

Dentro l'agente incollate la richiesta:

Leggi prova-markitdown.pdf e dimmi quante ore sono prenotate in totale per ciascun laboratorio.

Punto di controllo. Tra le azioni compare uvx ... markitdown. L'agente ve ne chiede il permesso: leggete il comando e rispondete sì solo se è quello. Poi ripetete con OpenCode, stessa richiesta. Se non compare, il file delle istruzioni non è stato letto: controllate nome, posizione e sessione nuova.

Passo 8. Pronti per la prima esercitazione

Se i sette controlli tornano, avete Claude Code e OpenCode collegati al server con la vostra chiave, il kit per leggere i documenti e le istruzioni globali per tutti e due. Il lavoro resta su questo PC: usate sempre lo stesso. Si prosegue con il foglio della prima esercitazione.

Se qualcosa non va

Che cosa vedete Causa probabile Che cosa fare
Claude Code chiede di accedere con un account Variabile creata dopo aver aperto la finestra, o nome diverso Finestra nuova, controllo «chiave presente» del passo 2
Errore 401, token non valido Chiave copiata male, spazio in fondo, o chiave di un altro PC Confrontate le ultime quattro lettere con il foglio e ricopiate la chiave
Il modello non è disponibile per la chiave Modello diverso dai due del corso Avviate con --model claude-sonnet-5-5
Pausa lunga, poi errore di connessione Indirizzo o porta sbagliati, o PC fuori dalla rete consentita Prova diretta del passo 3; se non risponde, chiamate il docente
L'elenco di OpenCode ha altre righe File non letto: sintassi o cartella Il file è opencode.json in .config\opencode; ricontrollate le virgole
Il file si chiama opencode.json.txt Salvato come «Documenti di testo» Salvate di nuovo con «Tutti i file» e cancellate il .txt
Errore sulla chiave in OpenCode, ma la chiave è giusta Un processo di OpenCode è rimasto acceso Il comando del passo 4 che ferma i processi, poi riaprite
OpenCode resta fermo, senza errori Indirizzo o porta nel file sbagliati Controllate baseURL: indirizzo del foglio, porta, /v1 in fondo

Per vedere le ultime quattro lettere della chiave che il PC legge, in una finestra nuova:

$env:ANTHROPIC_AUTH_TOKEN.Substring($env:ANTHROPIC_AUTH_TOKEN.Length-4)

uvx installato ma non trovato

Il messaggio dice che uvx o uv non è riconosciuto, dopo un'installazione finita senza errori. Prima chiudete la finestra e apritene una nuova. Se non basta, controllate che il file esista; deve scrivere True:

Test-Path "$env:USERPROFILE\.local\bin\uvx.exe"

Poi guardate se il percorso dell'utente contiene .local\bin:

[Environment]::GetEnvironmentVariable("Path", "User")

Se il file c'è ma il percorso non lo contiene, avvisate il docente. Nel frattempo si può lanciare uvx con il percorso intero:

& "$env:USERPROFILE\.local\bin\uvx.exe" --version

Cosa non fare

  • La chiave non va in un file di progetto, né in opencode.json, né in CLAUDE.md, né in un commit. Resta solo nella variabile.
  • La chiave non si mostra sul proiettore, non si fotografa, non si scrive in chat.
  • In OpenCode niente /connect (salva la chiave in un file) e niente /share (crea un link pubblico alla conversazione).

A fine corso

Togliete le due variabili dal vostro utente, un comando alla volta. Le finestre già aperte le vedono ancora finché non si chiudono.

[Environment]::SetEnvironmentVariable("ANTHROPIC_AUTH_TOKEN", $null, "User")

[Environment]::SetEnvironmentVariable("ANTHROPIC_BASE_URL", $null, "User")
