Promemoria: git per chi lavora con un agente

Un foglio da tenere accanto al terminale. Tutti i comandi sono quelli di git 2.23 o più recente (git --version dice quale avete). Documentazione completa: https://git-scm.com/docs

Leggere cosa è cambiato

Comando Cosa mostra
git status quali file sono cambiati, quali sono nuovi (Untracked), su quale ramo siete
git diff le righe cambiate nella cartella di lavoro, non ancora preparate per il commit
git diff --staged le righe già preparate con git add, cioè quelle che entreranno nel commit
git diff main tutto quello che differisce dal ramo main, cioè dalla partenza
git diff --stat solo l'elenco dei file e il numero di righe, per un colpo d'occhio
git show --stat HEAD che cosa contiene l'ultimo commit
git log --oneline i commit, uno per riga, dal più recente

Un file nuovo non compare in git diff finché non lo aggiungete: si vede con git status.

Salvare

git switch -c lavoro-filtro               # ramo nuovo per questo lavoro
git add src/logica.js test/logica.test.js # i file per nome, mai "tutto"
git diff --staged                         # ultima lettura
git commit -m "Elenco: filtro per laboratorio"

Un commit per ogni passo che avete controllato.

Tornare indietro

Situazione Comando
Modifica non ancora committata, su un file git restore percorso/del/file
Riportare un file com'è in main git restore --source=main percorso/del/file
Annullare solo alcuni blocchi di un file git restore -p --source=main percorso/del/file (per ogni blocco: y annulla, n tiene)
Togliere un file che l'agente ha aggiunto e già committato git rm percorso/del/file, poi git commit
Un commit già fatto è sbagliato git revert <id-del-commit> (crea un commit che lo annulla)
Tornare sul ramo di partenza git switch main

git restore sostituisce il file con la versione scelta: le modifiche non committate di quel file si perdono. Leggete prima git diff, nominate sempre il file.

Cosa non si usa in aula

  • git reset --hard: butta le modifiche non salvate di tutti i file.
  • git stash: mette da parte anche le modifiche che non sono vostre.
  • git clean -fd: cancella i file non tracciati.
  • git push: il repository di esercizio non ha remote e non deve averne.

Principio: niente operazioni distruttive sul lavoro condiviso. Se avete dubbi su cosa c'è nella cartella, create un ramo nuovo o chiedete.

Punti di partenza della palestra

git tag                                    # elenca i punti di partenza
git status                                 # prima: niente da perdere?
git switch -c lavoro-a2 partenza-a2        # ramo vostro (nome a scelta) dal punto noto
git switch main                            # per tornare alla base

Regole da dare all'agente (da adattare nel file di istruzioni del progetto)

## Uso di git
- Prima di una modifica ampia: fai un commit di partenza e lavora su un ramo nuovo.
- Aggiungi i file per nome (git add percorso). Mai git add . né git add -A.
- Non eseguire git push, git reset --hard, git stash, git clean senza chiedere.
- Per annullare una modifica usa git restore su un file nominato, oppure git revert.
- A fine lavoro elenca i file che hai cambiato; l'elenco sarà confrontato con git status.

Le soluzioni le ha il docente.
