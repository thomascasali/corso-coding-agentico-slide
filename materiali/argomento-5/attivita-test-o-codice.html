Attività: un fallimento, chi ha torto?

Durata indicativa: 10 minuti. Si lavora sulla palestra, nel repository del vostro PC.

La situazione

Un solo test fallisce. Non sapete se sbaglia il test o il codice. Prima di far lavorare l'agente, decidete voi, con una ragione scritta. L'agente corregge quello che avete deciso: non decide al posto vostro.

Passi

  1. Partite da un ramo nuovo. git status git switch -c lavoro-a5b partenza-a5-test-sbagliato node --test Annotate tests, pass, fail.

  2. Leggete il test che fallisce: nome, cosa verifica, dati che usa. Poi cercate la regola scritta. Dove? Il README della palestra, la cartella docs/, i commenti nel codice. Scrivete la vostra decisione in due righe, con la fonte: Sbaglia: il test / il codice Perché: ... (regola in ...)

  3. Chiedete all'agente di correggere ciò che avete deciso, citando la regola. Per esempio: «Il test X sbaglia, perché la regola in docs/... dice ...: correggi il test e non toccare il codice». Non scrivete «fai passare i test».

  4. Controllate il diff: git diff --stat git diff Ha toccato solo ciò che avevate deciso? Se ha cambiato anche l'altro, annullate quella parte.

  5. Verifica: node --test. Stessi tests del passo 1, fail 0.

  6. A coppie: confrontate la vostra decisione con quella del collega. Avete cercato la regola nello stesso posto? Se il documento non ci fosse stato, a chi l'avreste chiesta?

Provate anche così (facoltativo)

Su un secondo ramo (git switch -c lavoro-a5c partenza-a5-test-sbagliato) date all'agente solo: «Correggi il fallimento». Guardate cosa decide da solo e su che base. Confrontate il suo diff con il vostro.

Se qualcosa va storto

  • Il ramo è venuto male: ripartite con un altro nome da partenza-a5-test-sbagliato.
  • Un file che non riconoscete: guardate cos'è con git status prima di cancellarlo.
