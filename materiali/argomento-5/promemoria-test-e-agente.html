Promemoria: test e agente

Un foglio da tenere accanto al terminale. Il test runner è quello integrato in Node.js (versione 20 o più recente). Documentazione: https://nodejs.org/api/test.html (consultata il 9/11/2026).

Comandi

Comando Cosa fa
node --test esegue tutti i test del progetto (file in test/ e con nome *.test.js)
node --test --test-name-pattern="testo" esegue solo i test il cui nome contiene testo (è un'espressione regolare)
node --test test/logica.test.js esegue un solo file di test
git diff --stat -- test/ i test sono stati toccati?
git diff -- test/ come sono stati toccati

Come si legge l'esito

  • ✖ davanti al nome: il test è fallito. Il nome dice quale regola afferma.
  • Sotto, il messaggio (cosa si aspettava, cosa ha ottenuto) e le righe at ...: dove. La prima riga nel vostro codice è dove l'errore è stato lanciato; la causa può stare in chi ha chiamato.
  • In fondo: tests, pass, fail, skipped, todo. Un test todo non fa fallire il comando, uno skipped non viene eseguito.

Cosa chiedere all'agente, in ordine

  1. Riproduci: lancia solo il test che fallisce e incolla l'esito.
  2. Spiega con parole tue cosa si aspetta e cosa ottiene.
  3. Dimmi quali file hai letto e la tua ipotesi. Come la verifichi?
  4. Solo dopo: correggi.

Prima di accettare

  • [ ] Ho annotato tests, pass, fail prima della correzione.
  • [ ] Dopo: stesso numero di tests, fail 0, nessun skipped nuovo.
  • [ ] git diff --stat -- test/: se i test sono stati toccati, so dire perché.
  • [ ] Ho letto git diff dei file di codice: solo quelli che mi aspettavo.
  • [ ] Se test e codice erano in disaccordo, ho cercato la regola scritta prima di scegliere.
  • [ ] Ho provato a mano il caso, quando posso.

Righe da dare all'agente (CLAUDE.md)

## Test
- Prima di dire «fatto» lancia node --test e riporta i numeri di tests, pass, fail e skipped.
- Non modificare né cancellare un test per farlo passare. Se pensi che sia sbagliato,
  fermati e spiegami perché, citando la regola scritta.
- Non aggiungere skip o todo ai test esistenti.
- Un test che fallisce si riproduce prima di correggere il codice.

Sono contesto, non un divieto: il diff si controlla comunque.
