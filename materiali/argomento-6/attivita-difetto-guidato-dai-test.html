Attività: un difetto da trovare, guidati dai test

Si lavora sulla palestra (prenotazione dei laboratori, dati inventati), nel repository del vostro PC.

La situazione

Nella palestra c'è un difetto vero: un comportamento che le regole non prevedono. Due test lo mostrano, ma non dicono dove sta. Il vostro compito è farlo trovare e correggere all'agente senza dirgli voi la causa, e poi verificare che la correzione sia una correzione e non una scorciatoia.

Passi

  1. Controllate di non avere modifiche da salvare e partite dal punto noto (incollate i comandi uno alla volta). 
    git status

git switch -c lavoro-a6 partenza-a6


node --test
Annotate i tre numeri in fondo: tests, pass, fail. Vi serviranno al passo 5.

  1. Leggete voi i fallimenti, prima dell'agente. Per ognuno: il nome del test (che regola afferma?), il messaggio, la prima riga at ... che sta nel codice della palestra (non in node:internal). Scrivete in due righe cosa pensate che non vada. Non lo dite all'agente.

  2. Chiedete all'agente di riprodurre e spiegare, senza correggere. Un modello di richiesta, da incollare com'è: 

    Due test falliscono. Non correggere ancora.
1. lancia solo quei test e incolla l'esito;
2. dimmi con parole tue cosa si aspetta ciascuno e cosa ottiene;
3. dimmi quali file hai letto e la tua ipotesi sulla causa.
Poi fermati e aspetta.
    Per lanciare un test solo, sostituite parte del nome del test con un pezzo del nome prima di premere Invio: node --test --test-name-pattern="parte del nome del test". Confrontate la sua spiegazione con le vostre due righe. Dice la stessa cosa? Cita file e righe, o resta generico?

  3. Chiedete la correzione. Prima di accettarla guardate cosa ha cambiato (un comando alla volta): 

    git status


git diff --stat


git diff
Domande da farvi: ha toccato i test? Ha toccato solo i file che vi aspettavate? La modifica corregge la regola o aggiunge un caso speciale?

  1. Verifica finale, un comando alla volta. 
    node --test


git diff --stat -- test/
I numeri devono essere quelli del passo 1 con fail 0: stesso tests, nessuno skipped. Se sono diversi, l'agente ha cambiato i test o ne ha lanciati meno: tornate al passo 4.

  1. Provate anche a mano. La riga di comando usa la data di oggi, quindi fissate una data di "adesso" per le prove. In Git Bash, un comando alla volta: 
    export PALESTRA_ADESSO="2026-11-09T09:00:00"


node cli.js elenco --data 2026-11-12
In PowerShell: $env:PALESTRA_ADESSO = "2026-11-09T09:00:00". Guardate le prenotazioni di quel giorno e provate con node cli.js prenota --lab ... --docente d01 --classe 3A-INF --data ... --inizio ... --fine ... una prenotazione che, secondo le regole del README, dovrebbe essere accettata. Funziona come dovrebbe? Dopo ogni prova che scrive: git restore dati/dati.json.

  1. A coppie: confrontate la richiesta che avete dato all'agente e il diff che avete accettato. Avete dato la causa, o l'ha trovata lui?

Se qualcosa va storto

  • L'agente ha cambiato un test: non accettate. Chiedetegli di annullare quella modifica e di spiegare perché pensava fosse necessaria. Poi valutate voi.
  • I numeri del passo 5 non tornano: git diff --stat mostra quali file sono cambiati.
  • Il ramo è venuto male: git switch -c lavoro-a6-bis partenza-a6. Il lavoro vecchio resta sul ramo di prima.

Sul vostro progetto

Se il vostro progetto ha un difetto noto, provate lo stesso metodo: prima il test che lo mostra, rosso; poi la correzione; poi i numeri.
